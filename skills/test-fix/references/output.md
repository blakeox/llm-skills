# Test-fixing output

## Diagnosis

For each failure, state the test and error, root-cause class, causal evidence, fix, and confidence.

## Fixes

For each changed file, state what changed and which cause it addresses. Separate product bugs from test, fixture, environment, and timing defects.

## Remaining failures and flakiness

Name unresolved tests, current hypothesis, structural timing or state risks, and the evidence required to continue.

## Verification

Provide exact focused and broader commands actually run with results. Do not emit placeholder commands.

End with `What I did not verify`.
