# UI design output

## Screen intent and evidence

State the job of the interface, reviewed surfaces, evidence, and untested states or breakpoints.

## Findings

Order material UI failures using the shared finding contract. Cover hierarchy, layout, typography, color, affordance, component consistency, states, responsiveness, and accessibility only where relevant.

## System direction

Specify grid, spacing, type, color, component, and state rules. Name visual noise and duplicate controls to remove.

## Devil's advocate

State product, brand, or technical constraints that could change the recommendation.

## Verdict

- **Tighten it** — the structure is right but execution lacks rigor
- **Redesign the screen** — the intent is right but presentation blocks the job
- **Rebuild the system** — the screen reveals a broken component or hierarchy model

End with `What I did not evaluate`.
